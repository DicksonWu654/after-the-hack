# Incident data dictionary

`incidents_master.csv` is generated by `scripts/build_master.py` from the base
incident list, curated outcome layers, and sibling datasets. Reported amounts
carry source and verification qualifications. Unknown outcomes remain unknown.

| Field | Meaning |
| --- | --- |
| `loss_usd_reported` | Reported incident loss, with source and valuation described in `loss_basis`. |
| `returned_usd`, `returned_pct` | Source-reported return amount or share. A number alone does not establish a documented recovery; read `recovery_status`, `notes`, and `sources`. |
| `frozen_or_seized_usd` | Source-reported freeze, seizure, or other recovery amount; channel details describe the mechanism. |
| `recovered_pct_best` | Recovery share used for documented recovery estimates, capped at 100%; blank for `claimed_unverified`. Rounded percentages can show 0.0 for a small positive return. |
| `recovered_usd_capped` | Counted recovery USD, capped at incident loss. Uses reported USD before rounded percentages unless an explicit valuation override applies; zero for `claimed_unverified`. |
| `recovery_cap_flag` | Notes about source totals exceeding the incident loss and possible valuation or overlap issues. |
| `recovery_status` | `recovered_documented` means a source documents recovery, not necessarily independently verified; `recovered_unquantified` has no usable amount; `claimed_unverified` retains a claim without counting it as recovery. Other statuses distinguish checked sources with no recovery found from `unknown_not_checked`. |
| `voluntary_return_status` | `yes` counts a documented voluntary return; `claimed_unverified` is excluded from voluntary-return counts and dollars. Other values retain checked/unknown outcomes from source layers. |
| `recovered_channel`, `channel_class`, `channel_split` | Descriptive recovery mechanism, normalized mechanism, and explicit channel allocations where available. |
| `returner` | Actor label derived from channel text using the site's `returner_code` rules. Exactly `attacker`, `bot operators`, `MEV builder`, or `not identified`; it describes the actor named in the channel, not recovery certainty. |
| `headline_scope`, `in_headline` | Scope selection and final positive-loss/date filter; recovery recoding does not remove incidents from the loss denominator. |
| `outcome_evidence`, `verified_check`, `verification_sources` | Source and review qualifications; consult these before treating a reported return as verified. |

`returner` checks `recovered_channel` case-insensitively for `bot-operator`,
`bot operator`, or `mev-bot` first; then `mev builder`. It assigns `attacker`
when `channel_class` starts with `voluntary return`, the channel starts with
`voluntary`, or the channel mentions `attacker`, `hacker`, or `exploiter`.
Otherwise it assigns `not identified`. The label can remain present for a
claim or a non-return recovery: filter by recovery status and counted returned
USD before interpreting it as an observed return.
